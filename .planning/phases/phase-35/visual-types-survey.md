# Phase 35 — Canvas Visual Types Survey

> **Purpose**: Reference document for Phase 35 schema redesign. Maps all 11 canvas
> visual types — their `initialState` fields, per-step mutable fields, and highlight
> enums. Extracted from `spec.ts`, `spec.build.ts`, `types.ts`, renderers, and
> representative scene JSONs.
>
> **Date recorded**: 2026-04-26

---

## The Two Groups

Phase 35's optimization hinges on a structural distinction between two groups:

- **Group A — Static Topology**: structure is fixed in `initialState`; only state flags
  (highlight, status, active) change per step. These are candidates for sparse overlay.
- **Group B — Dynamic Structure**: items/entries/nodes are added or removed per step —
  that IS the algorithm. Full snapshots are the natural fit.

---

## Group A — Static Topology Types

### 1. `array`

Linear indexed sequence of values.

**`initialState`:**
```json
{
  "items": [
    { "value": 2, "highlight": "active", "id": "i0" },
    { "value": 7 }
  ]
}
```

| Field | Type | Required | Notes |
|-------|------|----------|-------|
| `items` | array | yes | Container |
| `items[].value` | any | yes | Cell value |
| `items[].id` | string | optional | Stable id for keyed animation |
| `items[].highlight` | enum | optional | See below |

**Additional overlay fields (step-only):**
| Field | Type | Notes |
|-------|------|-------|
| `pointers` | `{ index: number; label: string; color?: string }[]` | Labeled arrows (i, j, lo, hi) |
| `windowHighlight` | `{ start: number; end: number }` | Bracket over a range |

**Highlight enum:** `default | active | hit | insert | error`

**What changes per step:** `highlight` per item; `pointers`; `windowHighlight`.  
**What never changes:** `value` (traversal scenes), `id`.

---

### 2. `graph`

General directed/undirected graph with explicit nodes and edges.

**`initialState`:**
```json
{
  "nodes": [
    { "id": "A", "label": "Start", "highlight": "active" },
    { "id": "B", "label": "Node B" }
  ],
  "edges": [
    { "id": "e1", "from": "A", "to": "B", "label": "1", "highlight": "active" }
  ]
}
```

| Field | Type | Required | Notes |
|-------|------|----------|-------|
| `nodes` | array | yes | |
| `nodes[].id` | string | yes | |
| `nodes[].label` | string | yes | Display label |
| `nodes[].highlight` | enum | optional | |
| `edges` | array | yes | Required even if `[]` |
| `edges[].id` | string | yes | Unique edge id |
| `edges[].from` | string | yes | Source node id |
| `edges[].to` | string | yes | Target node id |
| `edges[].label` | string | optional | Edge weight or label |
| `edges[].highlight` | enum | optional | |

**Node highlight enum:** `default | active | visited | found`  
**Edge highlight enum:** `default | active`

**What changes per step:** `highlight` per node; `highlight` per edge.  
**What never changes:** `label`, `from`, `to`.

---

### 3. `tree`

Binary tree. Recursive structure via `left`/`right` children.

**`initialState`:**
```json
{
  "root": {
    "id": "n1", "value": "1", "highlight": "active",
    "left": {
      "id": "n2", "value": "2",
      "left": { "id": "n4", "value": "4", "left": null, "right": null },
      "right": { "id": "n5", "value": "5", "left": null, "right": null }
    },
    "right": {
      "id": "n3", "value": "3",
      "left": { "id": "n6", "value": "6", "left": null, "right": null },
      "right": null
    }
  }
}
```

| Field | Type | Required | Notes |
|-------|------|----------|-------|
| `root` | TreeNode \| null | yes | null = empty tree |
| `node.id` | string | yes | |
| `node.value` | any | yes | |
| `node.highlight` | enum | optional | |
| `node.left` | TreeNode \| null | optional | Absent node = null |
| `node.right` | TreeNode \| null | optional | Absent node = null |

**Highlight enum:** `default | active | found | visited`

**What changes per step:** `highlight` per node.  
**What never changes:** `value`, tree structure (for traversal scenes).

> **Note**: Edges are auto-generated by the renderer — never include edge data.

---

### 4. `grid`

2D grid for pathfinding, island counting, or maze problems.

**`initialState`:**
```json
{
  "cells": [
    [
      { "id": "r0c0", "value": 0, "highlight": "default" },
      { "id": "r0c1", "value": 1, "highlight": "wall" }
    ],
    [
      { "id": "r1c0", "value": 0, "highlight": "visited" },
      { "id": "r1c1", "value": 0, "highlight": "active" }
    ]
  ]
}
```

| Field | Type | Required | Notes |
|-------|------|----------|-------|
| `cells` | 2D array | yes | Outer = rows, inner = columns |
| `cells[r][c].id` | string | yes | e.g. `"r0c1"` |
| `cells[r][c].value` | any | yes | 0/1, char, etc. |
| `cells[r][c].highlight` | enum | optional | |

**Highlight enum:** `default | active | visited | wall | path`

**What changes per step:** `highlight` per cell.  
**What never changes:** `value`, `id`, grid dimensions.

---

### 5. `system-diagram`

System architecture diagram with components and connections.
The "worst offender" for redundant data — highest priority for Phase 35.

**`initialState`:**
```json
{
  "components": [
    { "id": "clientA", "label": "Client A", "icon": "mobile", "status": "active" },
    { "id": "ws1",     "label": "WS Server 1", "icon": "server", "status": "active" },
    { "id": "ws2",     "label": "WS Server 2", "icon": "server", "status": "normal" }
  ],
  "connections": [
    { "from": "clientA", "to": "ws1", "active": true, "label": "WS open" },
    { "from": "ws1", "to": "ws2", "active": false, "style": "dashed" }
  ]
}
```

**Components:**

| Field | Type | Required | Notes |
|-------|------|----------|-------|
| `id` | string | yes | |
| `label` | string | yes | Display name |
| `icon` | enum | yes | `server \| database \| mobile \| web \| compute \| cloud \| shield \| layers \| zap` |
| `status` | enum | yes | State field — changes per step |
| `sublabel` | string | optional | Secondary label (port, region, tech) |

**Connections:**

| Field | Type | Required | Notes |
|-------|------|----------|-------|
| `from` | string | yes | Source component id |
| `to` | string | yes | Target component id |
| `active` | boolean | yes | State field — changes per step |
| `style` | enum | optional | `solid \| dashed`, default: `solid` |
| `label` | string | optional | e.g. `"HTTPS"`, `"TCP:5432"` |

**Status enum (components):** `normal | active | overloaded | dead`  
**Connection state:** `active: boolean` (not a highlight enum)

**What changes per step:** `status` per component; `active` per connection.  
**What never changes:** `label`, `icon`, `from`, `to`, `style`, connection `label`.

> **Choreography rule**: when a request travels A→B→C, all three must have
> `status: "active"` AND both edges `active: true` simultaneously in that step.

> **No connection IDs currently** — Phase 35 adds `id` to connections in
> `initialState` so the sparse overlay can reference connections by id.

## Group B — Dynamic Structure Types

Structure (items/entries/nodes) is added or removed per step.
Full snapshots are the natural fit. Phase 35 defers optimization decision to OQ1
(measure actual byte waste before deciding).

---

### 6. `hashmap`

Key-value map. Entries inserted/removed as the algorithm runs.

**`initialState`:** `{ "entries": [] }` (always starts empty)

**Per step:**
```json
{
  "entries": [
    { "id": "e0", "key": "2", "value": "0", "highlight": "insert" },
    { "id": "e1", "key": "7", "value": "1", "highlight": "hit" }
  ]
}
```

| Field | Type | Required | Notes |
|-------|------|----------|-------|
| `entries[].id` | string | yes | Stable id for animation |
| `entries[].key` | string | yes | Always stringified |
| `entries[].value` | string | yes | Always stringified |
| `entries[].highlight` | enum | optional | |

**Highlight enum:** `default | insert | hit | remove`

---

### 7. `stack`

LIFO stack. Push appends to end; pop removes from end.

**`initialState`:** `{ "items": [] }` (always starts empty)

| Field | Type | Required | Notes |
|-------|------|----------|-------|
| `items[].id` | string | yes | |
| `items[].value` | any | yes | |
| `items[].highlight` | enum | optional | |

**Highlight enum:** `default | active | pop | push`

> Items are ordered bottom-to-top. Push = append to array. Pop = remove last.

---

### 8. `queue`

FIFO queue. Enqueue appends to end; dequeue removes from front.

**`initialState`:** `{ "items": [] }` (always starts empty)

| Field | Type | Required | Notes |
|-------|------|----------|-------|
| `items[].id` | string | yes | |
| `items[].value` | any | yes | |
| `items[].highlight` | enum | optional | |

**Highlight enum:** `default | active | enqueue | dequeue`

> Items are ordered front-to-back. Enqueue = append. Dequeue = remove first.

---

### 9. `linked-list`

Singly linked list. Nodes inserted/deleted per step; edges are auto-generated.

**`initialState`:** `{ "nodes": [] }` (typically starts empty)

| Field | Type | Required | Notes |
|-------|------|----------|-------|
| `nodes[].id` | string | yes | |
| `nodes[].value` | any | yes | |
| `nodes[].highlight` | enum | optional | |

**Highlight enum:** `default | active | insert | delete`

> **Never include edge data** — edges are auto-generated from node order by the renderer.

---

### 10. `dp-table`

2D dynamic programming table. Cells filled progressively (null → value).

**`initialState`:** All cells initialized with `value: null` or `0`.

**Per step:**
```json
{
  "cells": [
    [
      { "id": "r0c0", "value": 0, "highlight": "filled" },
      { "id": "r0c1", "value": 1, "highlight": "active" },
      { "id": "r0c2", "value": null, "highlight": "default" }
    ]
  ]
}
```

| Field | Type | Required | Notes |
|-------|------|----------|-------|
| `cells` | 2D array | yes | Outer = rows, inner = columns |
| `cells[r][c].id` | string | yes | e.g. `"r0c1"` |
| `cells[r][c].value` | any | yes | null for unfilled |
| `cells[r][c].highlight` | enum | optional | |
| `rowLabels` | string[] | optional | Row axis labels |
| `colLabels` | string[] | optional | Column axis labels |

**Highlight enum:** `default | active | filled | source`

> Structurally similar to `grid` but with DP-specific semantics and optional axis labels.

---

### 11. `recursion-tree`

N-ary recursion tree. Tree grows as recursion expands per step.

**`initialState`:** `{ "root": null }` (no recursion yet)

**Per step:**
```json
{
  "root": {
    "id": "f5", "value": "fib(5)", "highlight": "active",
    "children": [
      {
        "id": "f4", "value": "fib(4)", "highlight": "active",
        "children": [
          { "id": "f3a", "value": "fib(3)", "children": [] },
          { "id": "f2a", "value": "fib(2)", "children": [] }
        ]
      },
      { "id": "f3", "value": "fib(3)", "children": [] }
    ]
  }
}
```

| Field | Type | Required | Notes |
|-------|------|----------|-------|
| `root` | RecursionNode \| null | yes | null = before recursion starts |
| `node.id` | string | yes | |
| `node.value` | string | yes | Call label e.g. `"fib(4)"` |
| `node.highlight` | enum | optional | |
| `node.children` | RecursionNode[] | yes | **Always present** — use `[]` for leaves, never omit |

**Highlight enum:** `default | active | returned`

> **`children` is mandatory**, even for leaf nodes (`[]`). Never omit it.

## Quick Reference Summary

### State Fields by Type

| Type | Container | Item Fields | State-only Fields (change per step) |
|------|-----------|-------------|--------------------------------------|
| `array` | `items[]` | `value, id?, highlight?` | `highlight`, `pointers?`, `windowHighlight?` |
| `graph` | `nodes[], edges[]` | node: `id, label, highlight?`; edge: `id, from, to, label?, highlight?` | `highlight` on nodes + edges |
| `tree` | `root` (recursive) | `id, value, left?, right?, highlight?` | `highlight` per node |
| `grid` | `cells[][]` | `id, value, highlight?` | `highlight` per cell |
| `system-diagram` | `components[], connections[]` | comp: `id, label, icon, status, sublabel?`; conn: `from, to, active, style?, label?` | `status` on comps, `active` on conns |
| `hashmap` | `entries[]` | `id, key, value, highlight?` | entries added/removed |
| `stack` | `items[]` | `id, value, highlight?` | items pushed/popped |
| `queue` | `items[]` | `id, value, highlight?` | items enqueued/dequeued |
| `linked-list` | `nodes[]` | `id, value, highlight?` | nodes inserted/deleted |
| `dp-table` | `cells[][]` | `id, value, highlight?` | cells filled in |
| `recursion-tree` | `root` (recursive) | `id, value, children[], highlight?` | tree grows |

### Highlight Enums by Type

| Type | Values |
|------|--------|
| `array` | `default \| active \| hit \| insert \| error` |
| `graph` nodes | `default \| active \| visited \| found` |
| `graph` edges | `default \| active` |
| `tree` | `default \| active \| found \| visited` |
| `grid` | `default \| active \| visited \| wall \| path` |
| `hashmap` | `default \| insert \| hit \| remove` |
| `stack` | `default \| active \| pop \| push` |
| `queue` | `default \| active \| enqueue \| dequeue` |
| `linked-list` | `default \| active \| insert \| delete` |
| `dp-table` | `default \| active \| filled \| source` |
| `recursion-tree` | `default \| active \| returned` |
| `system-diagram` components | uses `status`: `normal \| active \| overloaded \| dead` |
| `system-diagram` connections | uses `active: boolean` |

## Key Constraints (Phase 35 Design Invariants)

1. **Stable IDs required**: All Group B types require `id` on every item/entry/node for
   Framer Motion keyed animation. Group A `array` items have optional `id?`.

2. **system-diagram has no connection IDs today**: Phase 35 adds `id` to connections
   so the sparse overlay can reference them. See CONTEXT.md §7.

3. **Edges auto-generated**: `linked-list` and `tree`/`recursion-tree` — never include
   edge data in JSON.

4. **`children` is mandatory in recursion-tree**: Use `[]` for leaves. Never omit.

5. **system-diagram uses status + boolean, not highlight**: Components use `status` enum;
   connections use `active: boolean`. This is unique among all 11 types.

6. **array is the only type with pointer overlays**: `pointers[]` and `windowHighlight`
   are additional state fields beyond `items`.

7. **dp-table and grid share identical cell structure** but have different highlight
   semantics and intended use cases.

8. **Group B always initializes empty**: `hashmap`, `stack`, `queue`, `linked-list`
   start with `initialState: { entries/items/nodes: [] }`. `recursion-tree` starts
   with `{ root: null }`. `dp-table` starts with all cells `null`.
